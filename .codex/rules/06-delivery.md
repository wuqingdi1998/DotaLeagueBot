# Правило 06. Сохранение и публикация без обходов

## Обязательный процесс

1. Закончи весь запланированный набор изменений и выполни точечные локальные
   проверки по правилу 05.
2. Убедись, что все относящиеся к задаче новые и изменённые файлы добавлены в
   Git.
3. Сохрани весь законченный набор изменений в Git с понятным описанием.
4. Отправь его в ветку `main` репозитория GitHub.
5. Дождись полного прогона в `validate` и успешного завершения
   `.github/workflows/deploy.yml` для отправленной версии. Это штатная полная
   проверка перед публикацией; отдельный полный локальный прогон не требуется.
6. Проверь публичный сайт после публикации.
7. Убедись, что локальная папка не содержит забытых изменений и совпадает с
   отправленной версией.

## Запрещено

- Оставлять завершённую работу только локально, если владелец прямо не попросил
  не публиковать её.
- Копировать или редактировать рабочие файлы непосредственно на сервере.
- Вручную перезапускать рабочую систему вместо штатного GitHub Actions.
- Отключать или пропускать проверки.
- Использовать `--no-verify`, `force push`, временные хаки и другие обходы
  стандартного процесса.
- Выдавать локально работающую версию за опубликованную.

## Если публикация не прошла

- Найди первопричину ошибки в штатном процессе.
- Исправь её в исходном коде или настройках проекта.
- Повтори затронутые локальные проверки; новая отправленная версия должна пройти
  полный прогон GitHub.
- Сохрани исправление в Git и снова отправь его в GitHub.
- Не исправляй рабочий сервер вручную.
