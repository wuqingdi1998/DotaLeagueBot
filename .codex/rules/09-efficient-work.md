# Правило 09. Экономия времени, инструментальных вызовов и контекста

1. Работай автономно. Не отправляй промежуточные отчёты после каждой команды,
   проверки или изменения файла. Сообщай только о критических проблемах,
   необходимости решения владельца и окончательном результате.
2. Не повторяй одинаковые проверки без причины. Сначала выполняй точечные тесты
   изменённого функционала, затем один полный прогон перед публикацией. Повторяй
   полную проверку только при изменениях, которые могли повлиять на уже
   проверенный код.
3. Не запускай повторные сборки без необходимости. Сначала закончи все
   запланированные изменения, затем собирай проект.
4. Не опрашивай GitHub CI/CD непрерывно. По возможности используй ожидание
   завершения процесса вместо многократных запросов статуса. Если доступен только
   опрос, используй редкие запросы с увеличением интервала при неизменном статусе.
5. Минимизируй количество инструментальных вызовов: объединяй независимые
   проверки, избегай повторного чтения неизменённых файлов и вывода больших
   логов. При ошибке выводи относящийся к ней фрагмент.
6. Не жертвуй надёжностью ради экономии. Сохраняй обязательные тесты, проверку
   публикации, обновлений структуры базы и целостности рабочей базы. Не отключай
   и не обходи обязательные проверки. Учитывай область изменения согласно
   правилам 05 и 06.
7. По завершении дай один короткий отчёт: что изменено, какие проверки пройдены,
   опубликовано ли обновление, есть ли проблемы. Для изменений только инструкций
   укажи, где они сохранены, и явно сообщи, что рабочий сайт не менялся.
