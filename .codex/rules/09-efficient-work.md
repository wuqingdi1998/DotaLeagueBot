# Правило 09. Экономия времени, инструментальных вызовов и контекста

1. Работай автономно. Не отправляй промежуточные отчёты после каждой команды,
   проверки или изменения файла. Сообщай только о критических проблемах,
   необходимости решения владельца и окончательном результате.
2. Сохраняй границы запроса. Исправляй причину проблемы и необходимые для результата
   зависимости; самостоятельные улучшения соседних разделов не включай в задачу.
3. Локально выполняй точечные проверки изменённого функционала. Штатный полный
   прогон выполняется один раз в GitHub перед публикацией по правилу 05. Не запускай
   целиком тот же набор на компьютере без предусмотренной правилом причины.
   После ошибки сначала повтори соответствующую проверку; после изменения кода
   полный прогон GitHub обязателен для новой отправленной версии.
4. Не опрашивай GitHub CI/CD непрерывно. По возможности используй ожидание
   завершения процесса вместо многократных запросов статуса. Если доступен только
   опрос, используй редкие запросы с увеличением интервала при неизменном статусе.
5. Минимизируй количество инструментальных вызовов: объединяй независимые чтения
   и проверки, избегай повторного чтения неизменённых файлов и вывода больших
   логов. Независимые действия выполняй одновременно, если они не меняют общие
   файлы, процессы или данные. При ошибке выводи относящийся к ней фрагмент.
6. Не жертвуй надёжностью ради экономии. Сохраняй обязательные тесты, проверку
   публикации, обновлений структуры базы и целостности рабочей базы. Не отключай
   и не обходи обязательные проверки. Учитывай область изменения согласно
   правилам 05 и 06.
7. По завершении дай один короткий отчёт: что изменено, какие проверки пройдены,
   опубликовано ли обновление, есть ли проблемы. Для изменений только инструкций
   укажи, где они сохранены, и явно сообщи, что рабочий сайт не менялся.
8. Сначала закончи запланированные изменения, затем собирай проект. Сохраняй и
   используй уже установленное окружение и результаты проверок для неизменённого
   кода. Не повторяй установку зависимостей, подготовку данных или сборку без
   необходимости. Обязательное создание и проверка рабочих образов в процессе
   публикации сохраняются; перестройка этого процесса является отдельной задачей.
