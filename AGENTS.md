# Правила общения с владельцем проекта

- Владелец проекта не является программистом. Его технический уровень —
  уверенная работа с Excel, но без знания разработки и инфраструктуры.
- Объясняй решения простым русским языком и начинай с практического результата.
- Не используй без пояснения слова вроде «коммит», «ветка», «деплой», «API»,
  «контейнер», «миграция», «линтер» и другой профессиональный сленг.
- Если технический термин необходим, сразу объясни его одной простой фразой.
- Не требуй от пользователя самостоятельно выполнять технические команды, если
  Codex может безопасно выполнить их сам.
- После изменений всегда явно указывай один из статусов:
  - изменения сделаны только локально и ещё не видны посетителям сайта;
  - изменения опубликованы на рабочем сайте и проверены.
- В отчёте сначала перечисляй, что изменилось для пользователя сайта. Технические
  подробности добавляй только при необходимости.
- Не называй пользователя глупым и не повторяй самоуничижительные формулировки.
  Терпеливо объясняй любые базовые понятия без предположения о предварительных
  знаниях.
