# Linken's Sphere Esports

Один репозиторий для Discord-бота, сайта и общей PostgreSQL-базы.

## Что находится в папках

- `bot/` — существующий Discord-бот на Python. Его команды и код React не смешиваются.
- `site/` — сайт на Next.js, React и TypeScript.
- `site/ARCHITECTURE.md` — обязательные правила структуры и размеров файлов
  сайта.
- `bot/database/migrations/` — изменения структуры общей базы.
- `scripts/` — единая локальная проверка проекта.
- `.github/workflows/` — автоматические проверки и развёртывание.
- `.vscode/` — подсветка ошибок, рекомендованные расширения и готовые задачи VS Code.

Бот и сайт используют одну PostgreSQL-базу, но отдельные таблицы. Существующие
таблицы `players`, лиг и регистраций бота сохраняются. Сайт ссылается на
`players.discord_id`, поэтому повторно регистрировать игрока на сайте не нужно.

Отложенные сообщения и действия также хранятся в PostgreSQL. Бот не опрашивает
их по короткому интервалу: база посылает сигнал при изменении расписания, после
чего бот ждёт точное время ближайшего задания. После перезапуска расписание
восстанавливается из базы автоматически. Так запускаются сообщения лобби,
анонсы, чек-ин, сроки выбора капитанов, Fearless Draft и Titan Checkup.

## Что уже умеет сайт

- настоящий вход через Discord;
- допуск только игроков, зарегистрированных в боте;
- профиль участника с Discord-аватаром, именем, игровым ником и позициями;
- отдельный режим организатора по серверному паролю, не связанный с обычным
  Discord-входом;
- постоянная главная сообщества и отдельный каталог всех турниров;
- создание и полное редактирование нескольких турниров через интерфейс;
- будущие, текущие, завершённые и архивные турниры;
- внесение матчей и результатов для прошлых событий;
- заявка команды с обязательной эмблемой и проверкой названия;
- ровно пять разных ролей Dota, капитан может занимать любую роль;
- приглашения игрокам и принятие/отклонение на сайте;
- уведомления от бота в личные сообщения Discord;
- передача капитанства принявшему приглашение игроку;
- решение организатора по заявке;
- формирование любого количества групп;
- создание матчей, BO1/BO2/BO3/BO5, счёт и статус;
- таблица групп, рассчитанная из завершённых матчей;
- check-in капитаном в настраиваемое окно перед матчем;
- светлая и тёмная темы, фирменный логотип, шрифты и цвета.

## Первый локальный запуск

Нужны Node.js 22+, Python 3.12+ и Docker Desktop.

1. Скопируйте `.env.example` в `.env`.
2. Заполните секреты Discord и PostgreSQL.
3. В Discord Developer Portal добавьте адрес возврата:
   `http://localhost:3000/api/auth/callback`.
4. Задайте отдельный пароль длиной от 12 символов в `ORGANIZER_PASSWORD`.
5. Запустите:

```powershell
docker compose up --build
```

Сайт откроется на `http://localhost:3000`. Главная страница работает независимо
от наличия турниров. После входа организатор открывает раздел «Турниры» и может
создавать будущие, текущие и архивные события. Каждый турнир получает отдельную
страницу, где во вкладке «Управление» добавляются команды, матчи и результаты.

Страница `/setup` остаётся запасным способом создать самый первый турнир во
время первоначальной настройки пустой базы.

Организатор может войти по отдельному серверному паролю без Discord-профиля и
без регистрации обычного аккаунта. Такой вход действует 2 часа. Обычный
Discord-вход по-прежнему доступен участникам и не получает права управления без
отдельного подтверждения. Пароль можно сменить в панели организатора; после
смены все прежние входы по паролю завершаются.

Для отдельной пустой локальной базы можно загрузить демонстрационные восемь
команд командой `psql -f bot/database/seed_demo.sql`. Файл помечен как
тестовый и не запускается ни миграциями, ни production-деплоем.

## Настройка Discord OAuth на сервере

В `.env` на сервере:

```dotenv
PUBLIC_BASE_URL=https://lsesports.ru
SITE_DOMAIN=lsesports.ru
DISCORD_CLIENT_ID=...
DISCORD_CLIENT_SECRET=...
ORGANIZER_PASSWORD=длинный_отдельный_пароль
```

В Discord Developer Portal добавьте:

```text
https://lsesports.ru/api/auth/callback
```

`DISCORD_CLIENT_SECRET`, токен бота и пароль базы никогда не добавляются в Git.
Если бот использует Google Sheets, оставьте существующий `credentials.json` в
корне репозитория на сервере: Docker подключит его внутрь контейнера только для
чтения.

## Проверки и публикация изменений

Новые обновления сначала публикуются на **https://dev.lsesports.ru**. Основной
сайт обновляется только после команды владельца. Порядок работы, вход и кнопка
отличий описаны в [инструкции тестового сайта](docs/development-site.md).

Постоянный порядок для всех задач задан в [AGENTS.md](AGENTS.md) и
[правилах проекта](.codex/README.md). Локально проверяются изменённые области;
единственный штатный полный прогон выполняется в GitHub перед публикацией.
Полный прогон на компьютере перед ним по умолчанию не нужен.

Первый раз:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r bot\requirements.txt -r bot\requirements-dev.txt
cd site
npm install
cd ..
```

Во время работы выбирайте конкретные тесты изменённого раздела. При изменении
интерфейса проверяйте затронутые экраны на компьютере и телефоне. Для изменений
прав доступа или работы с базой дополнительно проверяйте роли и сохранность
данных. Сначала завершите все запланированные правки, затем отправляйте их.

Отправка в `codex/dev` или `main` запускает полный набор проверок в задании `validate` процесса
[публикации](.github/workflows/deploy.yml). До его успешного завершения новая версия
не устанавливается. После публикации проверяются рабочий сайт и `/api/health`.

Для отдельной диагностики или по прямому запросу владельца сохранён полный
локальный запуск: в VS Code `Terminal → Run Task → Проверить всё`, либо:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\check.ps1
```

Он не заменяет проверки GitHub и не является обязательным повторным этапом перед
ними. Основания для его запуска описаны в [правиле 05](.codex/rules/05-testing-and-refactoring.md).

Полная проверка в GitHub включает:

- поиск критичных ошибок Python;
- проверку типов нового интеграционного кода;
- тесты бота;
- аудит уязвимостей Python-зависимостей;
- ESLint и строгую проверку TypeScript;
- тесты сайта;
- аудит npm-зависимостей;
- визуальные проверки и сравнение тестовой и рабочей сборок;
- production-сборку Next.js;
- проверку Docker Compose.

## Единое развёртывание

Push в `main` сначала запускает проверки. Только если они прошли, сервер:

1. получает код;
2. создаёт резервную копию PostgreSQL;
3. собирает Docker-образы;
4. применяет только ещё не выполненные миграции;
5. запускает базу, бота и сайт одним `docker compose`;
6. проверяет `/api/health`.

Существующий каталог данных `./postgres_data` остаётся тем же. Старый процесс
бота в PM2 удаляется только после успешной сборки новых образов.

На сервере необходимо один раз дополнить `.env` переменными из `.env.example` и
Публичные порты `80` и `443` должны быть открыты в firewall сервера.
Контейнер Caddy принимает запросы к `SITE_DOMAIN`, автоматически получает и
продлевает HTTPS-сертификат и передаёт запросы сайту. Порт сайта `3000` по
умолчанию доступен только на самом сервере.

## Отложенные объявления Discord

В `/say` можно указать необязательный параметр `отложить`: время и дату в формате
`HH:MM DD.MM.YYYY`, например `19:30 25.12.2026`. Время всегда московское.
На ввод текста следующим сообщением даётся 10 минут. После предварительного
просмотра нажмите «Отложить публикацию», чтобы сохранить пост в очереди.
Без даты кнопка сразу публикует объявление, как раньше.

Очередь хранится в базе вместе с изображениями и сохраняется после перезапуска.
Если бот был выключен в назначенное время, он отправит ожидающий пост после запуска.
Команда администратора `/postponed_del` отменяет все ожидающие посты текущего
Discord-сервера; уже опубликованные сообщения остаются на месте.

## Резервные копии

Перед каждым автоматическим развёртыванием создаётся
`backups/postgres-YYYYMMDDTHHMMSSZ.sql.gz`. Копии старше 14 дней удаляются.
Эмблемы команд находятся в `uploads_data/`; эту папку также нужно включить в
резервное копирование сервера.
