# Тестовая версия сайта

- Основной сайт: https://lsesports.ru.
- Тестовый сайт: https://dev.lsesports.ru.
- Вход на тестовый сайт: по паролю организатора, действовавшему на основном
  сайте при первоначальном копировании. Дальнейшие изменения паролей независимы.
  Discord-вход отдельно не настроен.

## Как выпускать обновления

Попросите Codex изменить сайт. Он сохранит обновления в `codex/dev`, проверит их
и установит на тестовый сайт. После этого можно открыть сайт и пробовать функции.
Пробные данные сохраняются между обновлениями.

Кнопка «DEV · i» внизу справа показывает номера тестовой и действующей версий,
а также список подготовленных изменений. Описания берутся из сохранённой истории
обновлений. Сравнение обращается к работающему основному сайту при каждом открытии
окна. Если точное сравнение невозможно, окно сообщает об этом.

Когда проверка закончена, напишите: «Опубликуй тестовую версию на основном сайте».
Codex перенесёт программу, выполнит обязательные проверки и проверит основной сайт.
Пробные результаты, настройки и загруженные файлы остаются на тестовом сайте.

Тестовый сайт закрыт от посторонних. Его нельзя использовать для проверки отправки
настоящих Discord-уведомлений: рабочий бот здесь не запускается.

## Устройство среды

GitHub запускает единый `validate` перед установкой каждой отправленной версии.
Задание `development` обновляет только `/root/DotaLeagueBotDev`; задание `deploy`
обновляет `/root/DotaLeagueBot`. Имена образов, базы, каталоги данных и сетевой
доступ к базам разделены.

Для первоначальной настройки предусмотрен ручной запуск GitHub с параметром
`bootstrap_development`: один полный `validate`, затем установка основного сайта
и тестового сайта из тех же проверенных образов. При обычной публикации в `main`
этот параметр выключен, поэтому тестовая среда автоматически не заменяется.

`scripts/deploy-development.sh` один раз получает согласованную копию рабочей базы
через `pg_dump`, очищает скопированные входы, переносит копию изображений и применяет
изменения структуры только к тестовой базе. Дальнейшие запуски сохраняют её.
В тестовую конфигурацию не попадают токен Discord-бота, пароль рабочей базы и
рабочий внутренний ключ планировщика.

DNS: запись `A`, имя `dev`, значение `147.45.134.133`. Общая служба Caddy принимает
запросы к двум доменам и автоматически получает HTTPS-сертификаты. У тестового
сайта нет отдельного открытого порта базы или приложения.
