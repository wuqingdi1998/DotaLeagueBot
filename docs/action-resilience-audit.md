# Проверка устойчивости действий сайта — 6 сентября 2026

## Подтверждённая причина

В журнале рабочего Caddy за 5 сентября UTC обнаружены POST-запросы
`/api/fearless-draft` с ответом 502 и пустым телом: 22:21:35–22:21:38
и 22:44:27. Сообщение сервера: `connect: connection refused`.
Это отказ соединения до передачи действия приложению во время публикации.
Соседние запросы драфта успешно обрабатывались за десятки миллисекунд.

Настройки в Git уже содержали ожидание перезапуска, но в фактически работающей
конфигурации Caddy отсутствовал `load_balancing`. Обычный `compose up` не
перезагружал настройки существующего прокси. При замене файла средствами Git
также нельзя полагаться на старое подключение одного файла в контейнер.

Скриншот сам по себе не содержит времени и номера запроса, поэтому связать его
с одной конкретной строкой журнала невозможно. Найденные отказы воспроизводят
описанное поведение.

## Изменения

- Штатная публикация применяет Caddyfile через stdin до замены приложения
  и повторно после запуска; проверяет фактически применённые настройки.
- Прокси ждёт восстановления соединения до 30 секунд для любого HTTP-метода.
  После передачи запроса повтор допускается только для GET/HEAD. Уже отправленные
  изменения не повторяются при потере ответа. Поведение сверено с
  [документацией Caddy](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy#load-balancing).
- Общая отправка JSON-запросов применяется ко всем найденным браузерным действиям:
  Fearless Draft, комнаты матчей, регистрация и чек-ин, календарь, турниры,
  заявки, составы, сетка, результаты, сезон, участники, архив, фон профиля,
  компендиум, прогнозы, задания, режим организатора, перерыв сайта и выход.
- Одновременные одинаковые изменения объединяются, включая формы с тем же
  выбранным файлом. Разные команды и разные файлы не объединяются.
- Время ожидания включает чтение тела ответа: 45 секунд для чтения данных,
  90 секунд для изменений. Пустой/оборванный ответ 200 не считается успехом;
  явный 204 принимается. Ошибки проверки данных 4xx сохраняются.
- При неопределённом результате выводится просьба сверить данные перед повторным
  нажатием. Автоматического повторения записей в браузере нет.
- В драфте результат выбора стороны/очерёдности и героя сверяется с текущим
  состоянием после потерянного ответа. Проверяются конкретные игрок, карта,
  шаг и выбор, а не просто изменение номера версии.
- Драфт и комнаты немедленно блокируют параллельную отправку. Ошибка обновления
  экрана после подтверждённой записи не превращает её в неуспешную.
- Ходы тренировочного бота выполняются после ответа на сохранённое действие.
  Ошибка отдельного слушателя обновлений не отменяет успешный результат записи.
- Выход из профиля проверяет ответ перед обновлением страницы.

## Проверки

- Автоматические тесты общей отправки: все методы записи, потерянный ответ,
  повреждённый JSON, пустой 200, 204, 429 и Retry-After, зависшее тело ответа,
  отсутствие сети, отмена чтения, одинаковые/разные команды и загрузки файлов.
- Тесты сверки драфта исключают ложное подтверждение по действию соперника,
  другой карте, другому шагу, герою или автоматическому выбору по таймеру.
- Общий тест проверяет, что браузерные записи не обходят защищённую отправку.
- Изолированный настоящий Caddy 2.11.4: GET/POST/PUT/PATCH/DELETE, отправленные
  до запуска приложения, успешно дождались его и пришли по одному разу.
  POST с оборванным ответом после получения сервером не был повторён.
- Настоящий React-хук драфта проверен в Chrome на изолированной странице:
  потерянный ответ после сохранения, отказ без сохранения, отказ обновления после
  успешной записи, два вызова отправки в одном событии.
- Полный набор проверок проекта выполняется перед публикацией; рабочие
  настройки прокси и `/api/health` дополнительно проверяются после неё.

Проверка охватывает общий путь отправки и код всех найденных браузерных действий.
Реальные удаления, результаты матчей, начисления и сообщения участникам ради
тестирования на рабочей базе не выполнялись. Между разными вкладками или
устройствами объединения запросов нет: там продолжают действовать проверки,
блокировки и ограничения базы данных соответствующего раздела.
